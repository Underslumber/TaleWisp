## Shared API

- `GET /api/workspace/catalog`: `{authors:[{id,name,series:[{id,name,books:[{id,name}]}]}],active:{authorId,seriesId,bookId},revision}`. Opaque IDs derived from relative verified folders/metadata; never accept client filesystem roots. Include a clear legacy/unassigned grouping rather than silently hiding existing cards. Catalog root: explicit options.catalogVaultPath / TALEWISP_CATALOG_VAULT / repository vault; active persisted series may be a fallback for fixtures.
- `POST /api/workspace/select {authorId,seriesId,bookId}`: validated catalog membership, refuse during a running agent turn, persist selection, shut down/rebind agent to selected series before next turn. Returns catalog shape. Prior dirty app drafts retain their own binding. No source migration or rewriting.
- `GET /api/workspace/overview`: `{active,manuscripts:[{path,title,type,words,status}],notes:[{path,title,type}],progress:{words,targetWords,draftCount,completedCount},style:{available,excluded,paths},capabilities:[{name,title,mode,description}]}`. Existing-book manuscript list is source-bound; app writing progress includes bound local drafts. No fabricated completion; goals explicit optional.
- Documents and notes gain `authorId,seriesId,bookId,status,targetWords` where applicable. Existing rows remain unassigned until explicit binding; retain bytes/history. GET lists default active scope with `?scope=all` to show all. Create binds selected scope; update cannot silently rebind. Optional explicit `POST /api/documents/:id/bind` binds to current selection with version guard. `PUT /api/documents/:id` may update status/targetWords alongside existing title/text/version.
- `GET /api/knowledge/cards?type=&q=`: `{cards:[{path,title,type,excerpt,status,linksCount}],truncated}`. Search scoped selected series, entire eligible indexed set with explicit bounds/omissions. Raw frontmatter and wikilink brackets never appear in excerpts.
- `GET /api/knowledge/card?path=`: `{path,title,type,body,revision,metadata,links:[{target,label,path,status}],backlinks:[{path,title}],truncated}`. Safe Markdown body (not HTML); frontend renders safe DOM with headings/paragraphs/lists/emphasis/wiki/Markdown links. Resolve links using current-relative, vault-relative, unique suffix/basename; ambiguity shown, never silently choose. Reject traversal/symlink/unsafe schemes. Existing `/knowledge/file` retains raw text for exact source context.
- `GET /api/proposals`: `{proposals:[{id,title,path?,tool?,state,summary,createdAt}]}`. `GET /api/proposals/:id`: concrete `{id,title,state,path?,before?,after?,diff?,tool?,arguments?,summary,baseRevision?,workspaceRevision}`. App-owned pending store, no author vault write on proposal creation.
- `POST /api/proposals {path,text,title?,summary?,baseRevision?}`: prepare create/update file within active series; verify existing revision when provided; snapshot exact before and intended after, return proposal. `POST /api/proposals/:id/apply {confirmed:true}` verifies active scope and source hash, creates backup, safely applies exact proposal; repeated successful apply idempotent, changed source conflicts. Agent cannot call this endpoint. `POST /api/proposals/:id/reject {}` marks rejected without modifying vault.

## Runtime and plugin bridge

Backend service factory `createWorkspaceService({catalogVaultPath,initialVaultPath,store,dataDir})` returns catalog(), select(ids), overview(), cards(query), card(path), root(), selection(), revision(), prepareProposal(payload), listProposals(), proposal(id), applyProposal(id), rejectProposal(id), queueAction({tool,arguments,summary}), applyAction callback registration if needed. Root integration may adjust exact import signatures; workers must report deviations before frontend dependencies.

Agent receives `workspaceService` and `pluginService` from createApplication. `AgentService.setWorkspace({vaultPath,selection,revision})` rejects active turn, shuts down old runner/thread, clears cross-workspace messages/context; it retains isolated login credentials. New bridge runs via MCP stdio and invokes private internal server endpoint, protected with a random per-server bearer token, loopback connection and pinned origin; token stays in child environment/config, never browser/output/export. Private calls explicitly bound to current workspace revision.

Plugin service exposes the actual installed TaleWisp tool inventory, read-only operations execute; mutation tools queue a concrete reviewable action, never auto-apply. Existing proposal save/apply map to the app-owned preview/apply boundary; model cannot forge approval. Select-vault uses catalog selection only; no arbitrary path. Native plugin guards for imports, StoryArt receipt and other operations remain effective; unsupported external dependencies are shown honestly. Full workflows appear in capability menu, with required input/action rather than dead buttons.

Agent prompts include active author/series/book, requested mode, current draft snapshot, explicit sources and appropriate TaleWisp production instructions. Style writing uses only selected applicable confirmed rules and lexical preferences; preserve the selected series' explicit exclusion. Style requires actual usable evidence, no invented style profile or automatic calibration.
