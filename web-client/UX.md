# UX: обязательная авторская поправка 2026-10-14

Точный запрос:

1. «изначально должна быть темная тема. поищи лучшие практики.»
2. «Нужен доступ к инструментам с основной вкладке, и чтобы была возможность с ним работать с главной вкладки. она основная. У нас есть текст и вызываемые инструменты.»
3. «должно быть адаптировано и под мобильные платформы, я бы сказал под них в первую очередь».

Поправка отменяет светлую тему по умолчанию и прежнюю визуальную приёмку. Остальные требования сохранены: агент по подписке без платного API, работающий редактор/хранилище, инструменты TaleWisp, Google Docs, локальный и серверный запуск, авторский контроль смысловых изменений.

## Прочитанные рекомендации

| Источник | Подтверждённая рекомендация | Применение в клиенте |
|---|---|---|
| [Apple UI Design tips](https://developer.apple.com/design/tips/) | Сенсорные цели 44×44 points; содержимое без горизонтальной прокрутки; органы управления близко к содержимому | Для веба выбран проектный ориентир 44×44 CSS px; инструменты текста на основном экране |
| [WCAG Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) | Контраст обычного текста ≥4.5:1, крупного ≥3:1 | Проверить фактические вычисленные цвета основных текстов, подсказок и полей |
| [WCAG Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) | Перестройка содержимого при ширине 320 CSS px | Проверить редактор и панели на 320/390 px без горизонтального переполнения |
| [WCAG Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) | Минимум 24×24 CSS px с оговорёнными исключениями; крупные цели удобнее | Цель проекта 44 px для основных мобильных действий выше минимума WCAG |

Material 3 и Apple Dark Mode также найдены, но их страницы вернули JavaScript-only вместо доступного текста; не объявлять содержание этих страниц прочитанным или проверенным. Тёмные семантические цвета здесь — проектное решение, проверяемое по фактическому контрасту.

## Критерии результата

- Первый показ нового клиента — тёмный, включая поля, меню и диалоги; без светлой вспышки.
- Главный экран — документ и вызываемые инструменты, а не каталог переходов. Действия относятся к активному документу/выделению.
- Панели инструментов, контекста и чата сохраняют рабочий текст и выделение. Предложение агента остаётся предложением до действия автора.
- Мобильный поток первичен: удобный редактор, крупные цели, доступ к инструментам одной рукой, safe-area и доступность при экранной клавиатуре.
- Десктоп расширяет тот же поток; редактор не сжимается ради постоянного показа всех вторичных панелей.
- Проверки: 320/390 px и десктоп; доступ с главного экрана; корректный исходный объект инструментов; сохранение при переходах; контраст и hit areas; возвращение фокуса после закрытия панели.

Наличие CSS/тестов не заменяет визуальную и функциональную проверку. Эти критерии ещё требуют подтверждения на итоговой версии. Браузерный viewport не является доказательством работы реальной мобильной клавиатуры на устройстве.
