# Source-grounded continuity extraction (opt in)

Use when the author asks to prepare explicit continuity records from supplied local Markdown/TXT sources. Ordinary prose production does not invoke this route. This is a bounded preparation step for [continuity-contract.md](continuity-contract.md), not a whole-vault import, database or automatic canon update.

1. Call `talewisp_prepare_continuity_extraction` with explicit vault-relative `source_paths`. Give the **entire** returned packet to the extractor; never summarize or truncate source text. The helper reads strict UTF-8 (optional BOM), hashes original bytes, and rejects more than 16 files, 256 KiB per file or 512 KiB combined source bytes. Split an oversized request into explicit author-visible scopes; do not describe a partial packet as complete.
2. Resolve model/effort through `talewisp_model_selection` under [model-selection.md](model-selection.md) before each dispatch. Dispatch one logical `vault_curator` as extractor using [host-portable dispatch](agent-routing.md#host-portable-dispatch); generic host agents are the fallback, with the same explicit role and resolved model/effort. Pass the full packet, `output_schema`, current continuity v1 schema and the extraction rules below. This host agent actually reads and extracts; Python does not infer semantics and no external LLM API client is added.
3. Dispatch a **different independent host agent** as `continuity_reviewer` (portable fallback as above). Pass full raw packet, literal candidate, v1 schema and `review_schema`; do not pass a preferred verdict. It reviews every record's entire claim, evidence, chronology and references, reporting `supported`, `contradicted` or `unknown` with a concrete reason. Its receipt binds both the candidate digest and each full record digest using the helper's `digest` (canonical JSON: sorted keys, compact separators, UTF-8, literal Unicode, no non-finite numbers). Return machine JSON, without prose fences. Declared agent IDs document distinct dispatch provenance; they are not cryptographic identity or proof of independence. Retain actual host dispatch evidence when assessing that distinction.
4. Show the extracted candidate, all review verdicts and coverage to the author. Unknown/contradicted records and unknown chronology remain draft/proposal; never silently remove them. Stop on a malformed record/review or source drift and describe the exact defect. Do not run hidden extraction/review loops.
5. Only when the author explicitly asks to save, call `talewisp_stage_continuity_extraction` with `source_paths`, `source_packet_sha256`, literal `candidate`, literal `review`, `target_path` and optional `title`. Target must be a new vault-relative standalone `.json` continuity contract. Existing contracts and manuscripts cannot be replaced in this bounded route. This uses `talewisp_save_proposal` and returns a pending preview; canonical target remains unwritten. Preview statuses describe the **intended post-approval** result, not accepted canon. Show this exact preview before approval.
6. Only after explicit author approval call existing `talewisp_apply_proposal` with the pending `proposal_path` and `confirmed: true`. The extraction receipt, exact candidate/review/preview binding, replacement, every source's raw bytes and target snapshot are checked again before writing. A mutated or missing receipt fails closed. This is drift/tamper detection within local proposal files, not signed hostile-storage attestation. Existing generic proposals keep their current route. Run requested continuity audit or knowledge projection on the approved contract; report at most listed-record coverage.

## Extraction and review rules

Candidate envelope: integer `version: 1`, `extractor_id`, `source_packet_sha256`, `coverage` and all four arrays (`scenes`, `entities`, `facts`, `assertions`). Coverage is `{scope: "supplied_sources_only", complete: boolean, omissions: [nonempty explanations]}`; `complete: true` requires no declared omissions and means the supplied scope only. Each row carries a unique ID within its collection, nonempty full `claim`, `status: "proposal"` or `"draft"`, exact evidence and v1 fields. Unknown scene `story_order`/`narrative_order` is explicit `null`; never guess chronology from file names, array order or model lore. Supported scenes require both finite numeric orders. Record limits are 5000 total.

The semantic reviewer checks the **entire record**, not just the separate claim sentence: an entailed identity with invented chronology is unknown/contradicted. Facts distinguish narrated world truth from beliefs; character `learn` and reader `reveal` are separate events. Missing access is unknown, not implicit knowledge. Evidence is a literal quote in the supplied current source, with its vault-relative path and raw-byte hash. Supporting a quote's existence is gate one; judging whether it entails the full interpretation is gate two. Gate two is a model verdict with explicit uncertainty, not deterministic Python semantic validation.

Review envelope: `type: "independent_semantic_review"`, different nonempty `reviewer_id`, `source_packet_sha256`, `candidate_sha256`, exhaustive `records`. Each entry has `record: "collection:id"`, `record_sha256`, `verdict` and nonempty `reason`. Duplicate, extra, omitted or stale receipts are rejected. Structurally invalid records fail regardless of a supported verdict. A supported assertion whose required entity/fact/scene is unconfirmed remains a proposal with `promotion_blocker: "unconfirmed_dependency"`.

The approved v1 contract preserves **all** records and review verdicts, confirms only supported structurally valid records with supported references, and includes scoped coverage plus hashes. Unconfirmed rows cause the current checker to report `INCOMPLETE`; a reviewer cannot grant canon approval. Author approval is gate three. Coverage omissions also remain visible in the contract; the checker audits listed records only and cannot independently prove extraction completeness. No inference of unlisted facts or universal PASS follows.

Original implementation uses the provenance-versus-semantic-support distinction discussed by [LoreGraph](https://github.com/YunyueLi/LoreGraph); no upstream code or runtime dependency is bundled.
