# StoryArt: полноценное рабочее пространство в WebUI

## Буквальное ТЗ

2026-10-22: «Может внедрим удобный интерфейса взаимодействия со storyart в наш webui? Давай проработает интеграцию, а сам ui ты отдашь опусу. До сброса лимитов разрешаю использовать астру».

Последняя поправка: «нужно сделать полноценный интерфейс взаимодействия, с карточками стилей в виде картинок, с возможностью просмотра описания стиля. с инструментом создания стиля, с генерациями, чтобы видеть какие референсы подключены, и тд этапы процесса, нужно продумать удобный нативный интерфейс работы с проектом».

Поправка заменяет узкий первоначальный вариант формы сообщения и списка задач. Заполнение composer не считается созданием стиля или генерации. Требуется самостоятельное рабочее пространство с настоящими действиями.

Последующие указания: «не забывай делегировать точечные задачи судагентам»; «когда лимит упадет ниже 10% астру использовать нельзя, максимум sol 6.1 мед»; «еще агентам опен аи вроде луны, точечные задачи на них! Опус только дизайн и итоговое ревью». Действующий маршрут: Opus — дизайн и единый итоговый аудит; точечные задачи — OpenAI/Luna, обязательное инженерное ревью — Sol 6.1 Medium. Astra не запускалась. TaskWarden хранит актуальное ТЗ версии 3; прежняя роль реализации Opus исключена из дальнейшего dispatch.

## Проверенная основа

Штатный scripts/storyart.ps1 style_pack_manager list-styles --json вернул шесть локально готовых стилей: AROMA, KATE_FOX, KRYSDECKER, LORANDESORE, RIOT_LOL_SPLASH, Sciamano240. web_readiness=NOT_PREPARED означает отсутствие сокращённого экспорта и не запрещает локальную работу через WebUI.

Источники StoryArt: tools/style_pack_manager.py (каталог, init/ingest/classify/finalize, планы, approval), tools/task_execution_guard.py (привязка к чату, стадии, попытки), tools/generation_call_contract.py (физические вложения), tools/character_profile_state.py (персонажи), docs/REQUEST_FIDELITY.md, .agents/STYLE_PACK_WORKFLOW.md. WebUI уже имеет storyart-service.mjs, scoped журнал, desktop transport, защищённые изображения. Исходники и авторские данные StoryArt из TaleWisp не изменяются.

## Рабочие поверхности

| Экран | Содержание | Действия |
|---|---|---|
| Мастерская | Визуальные карточки стилей, поиск, готовность, текущие работы | Открыть стиль, создать стиль, новая генерация |
| Стиль | Большой образец, сохранённое описание и ограничения, одобренные референсы с ролями, персонажи | Использовать стиль, создать персонажа/генерацию |
| Создать стиль | Название, намерение, загрузка исходных картинок с миниатюрами, обзор перед запуском | Начать обработку одним действием |
| Новая генерация | Стиль, тип результата, персонаж при необходимости, сцена/детали/запреты, параметры, выбранные референсы | Запустить выделенный запрос |
| Работа | Большой результат, этапы, причина ожидания, подключённые референсы, кандидаты этой работы | Поправка, продолжить, согласовать конкретный результат |
| Библиотека | Одобренные референсы и персонажи выбранного стиля, результаты своих задач | Просмотреть и выбрать допустимый источник |

Раздел занимает главное поле. На desktop изображение в центре, процесс и настройки рядом; на mobile последовательные вкладки и доступные действия. Узкий drawer остаётся быстрым входом, а не вместилищем всей мастерской. Редактор, Google, выделение и черновики сохраняются. IDs и сырой ответ скрыты в диагностике. Стилистика TaleWisp, без новых зависимостей.

## Потоки

```text
StoryArt → Стили → Карта стиля → Описание / Референсы / Персонажи
                           └→ Новая генерация
Создать стиль → Имя + исходники → Обработка → Проверка → Утверждение
Генерации → Работа → Результат + этапы + референсы → Поправка / согласование
```

## Семантика

- Каталог читает реальные packs без миграции legacy. Обложки и миниатюры берутся из зарегистрированной библиотеки стиля. Одобренные якоря, опубликованная legacy-библиотека и зарегистрированные TEST-образцы показываются с разными статусами; TEST не означает одобрение. История чужих генераций, pending и REJECTED не сканируется. Недоступное изображение отмечено честно.
- Описание стиля берётся из сохранённого профиля, не сочиняется root. Ограничения переноса показаны отдельно.
- Три независимых состояния референса: выбран автором; подготовлен в плане; зафиксирован в исполненном вызове. Роли и происхождение видны. Выбранное не называется фактически подключённым.
- Этапы основаны на состоянии привязанного запроса. Никаких процентов по таймеру. Для CHARACTER_BASE лицо/фронт/бок/спина/сборка; остальные работы имеют собственную цепочку.
- VISUAL_QA, CANON_QA и согласие автора раздельны. completed не означает утверждённый арт. Одобрение отправляет согласие на конкретный файл и хеш; сохранение подтверждает StoryArt.
- Каталог стилей общий для локального StoryArt. Работы, загрузки и формы изолированы по выбранной области TaleWisp. Поздние ответы прежней области не попадают в новую.
- Стиль, степень переноса и дополнительные библиотеки выбираются отдельно. Выбор стиля не включает библиотеку автоматически. Для главного персонажа сначала утверждённая идентичность, затем сцена.

## Интеграция

Ограниченный read-only адаптер читает реестры и профили StoryArt. Изображения выдаются только по серверным идентификаторам зарегистрированных ресурсов. Загруженные автором файлы хранятся в служебном каталоге TaleWisp. Создание стиля/персонажа/генерации передаётся в выделенный StoryArt-чат через desktop transport; поправки и approvals идут в тот же чат. StoryArt выполняет штатные инструменты. Прямой генератор из TaleWisp, запись в StoryArt, произвольный shell/file proxy запрещены.

Открытие раздела и preview ничего не генерируют. Неопределённый исход dispatch не повторяется автоматически. Не допускается фальшивый success или декоративный stepper вместо реального состояния. При недоступном transport каталог остаётся читаемым; запуск показывает конкретную недоступность.

## Приёмка

| ID | Требование | Доказательство |
|---|---|---|
| A1 | UI разработан Opus | TaskWarden receipt, входной hash, modelUsage |
| A2 | Карточки с картинками, описания, самостоятельная мастерская | Реальный каталог, desktop/mobile screenshots |
| A3 | Создание стиля с исходниками | Upload, scoped dispatch, честные ошибки |
| A4 | Генерации и управление работой | Реальные handlers/API, idempotency tests |
| A5 | Видимость выбранных/подготовленных/исполненных референсов | План/вызов и проверка отсутствия ложного attached |
| A6 | Реальные этапы и approvals | Unknown/wait/error/complete tests, конкретное согласие |
| A7 | Сохранность прежних возможностей | Регрессионные тесты, визуальная QA |
| A8 | Границы доступа и файлов | Path/symlink/scope/size/auth tests, независимое ревью |

Тесты на фикстурах и чтение реального каталога не заменяют сквозную реальную генерацию. Не запускать платную/квотную генерацию или создание реального стиля ради теста без отдельного задания на конкретный результат.
