## Продукт

- Автор → серии → самостоятельные книги. Google Docs и другие исходные файлы — сопутствующие материалы книги, не экземпляры книги. Выбор книги открывает рабочее пространство/черновики книги, НИКОГДА автоматически Google Docs. Документ открывается только отдельным явным действием по плитке вложения. Убрать «оригинал книги» из метаданных карточки и сообщений там, где речь о сопутствующем файле.
- В «Настройки» отдельный заметный вход «Настройки проекта». Красивые понятные плитки авторов, серий, книг и связанных файлов с путём, текущими связями, именами, компактными явными действиями. Можно переименовать автора/серию/книгу/отображаемое имя файла и менять связи: серия→автор, книга→серия, файл→книга. Показать последствия/цель, сохранить/отмена, ошибки/загрузка/пустые состояния, удобный мобильный вариант. Независимая книга может существовать без Google Docs, надо уметь создать книгу и прикрепить имеющийся Google Doc URL/ID и/или доступный локальный источник. Добавление логических автора/серии допустимо при необходимости полноценной настройки, без генерации художественного содержания. Удаление не требуется.
- Архивировать сопутствующий файл обратимо: исчезает из рабочего списка, остаётся в отдельном разделе «Архив связанных файлов» внутри настроек с именем/книгой/серией и кнопкой «Восстановить». Архивируется связь/метаданные приложения, НЕ Google Drive и НЕ исходник vault. Запрещено trash/delete Google Docs, удалять/перемещать/переименовывать физические авторские файлы или переписывать канон. Если один источник связан с несколькими книгами, не распространяй архивирование одной связи на другие молча.

## Данные и безопасность

- Имена, иерархия и связи должны храниться устойчиво на сервере в app-owned .data/SQLite, а не только DOM/localStorage. Стабильные ID независимы от названия; переименование не создаёт новые сущности. Связи валидируются целиком, чужие/отсутствующие IDs не принимаются; версии/конфликт409 для конкурентных правок. Конкретные исходные пути/происхождение сохраняются. Настройки не должны менять реальные инструкции/канон автора.
- Существующие 8 «книг» первой серии на деле источники. Автор ЯВНО подтвердил: одна книга «Мир под гнетом магии», все8файлов прикреплены к ней. Реальные IDs будут переданы отдельным migration-map.json: реализуй явный dry-run/apply механизм миграции с проверками идентичности и идемпотентностью. Не запускай его: root снимет backup и выполнит после critical-аудита. Не делай автоматическое эвристическое объединение по похожим названиям. Остальную серию/материалы не объединять без отдельной карты.
- Сохранить старые черновики/заметки/историю/предложения/сообщения и доступность контекста прежних8IDs. Явная карта alias/перенос должна сохранять owner/series/book scope, не смешивать чужой контекст и не обнулять историю. При смене связей scoped drafts/notes/proposals/messages и выбор должны корректно переехать/согласоваться транзакционно или через строгую alias-логику; нельзя только визуально поменять каталог и потерять строки под прежними scopeKey. Если активная книга перемещается, контекст агента/источники сбрасываются или переключаются только после flush и подтверждения сервера; запрещена конкуренция с running/pending turn. Возвращай ошибки до записи, без частичных изменений. Ревизия workspace должна учитывать overlay-настройки.
- Карту знаний, источники, StoryArt, GoogleOAuth, импорт, предложения, экспорт, save/conflict/security сохранить. Не превращать все8вложений в основной текст/слова книги. Сопутствующие материалы доступны отдельно; существующие series-scope знания не теряются. Нельзя подменять реальные статусы mock-успехом.
- Backend auth/Origin/CSRF/secrets не менять и не ослаблять. Новые routes проходят те же проверки, не раскрывают абсолютные пути/секреты. Выходной экспорт должен включать новые сущности/связи/архив, сохраняя старые записи. Перед записью исходников authorvault запрещено ВСЁ: такие файлы отсутствуют в кандидате.
