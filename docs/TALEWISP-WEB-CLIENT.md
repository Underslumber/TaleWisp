# TaleWisp Web Client — проект v0.1

Дата: 2026-10-14. Статус: предложение архитектуры, а не реализованное приложение.

## Задание и границы

Спроектировать веб-клиент TaleWisp: агент через подписку ChatGPT/Codex, редактор, база знаний, Google Docs; запуск на собственном компьютере или сервере. Отдельный платный OpenAI API исключён. Google Docs/Drive API для интеграции документов — отдельная технология, не маршрут оплаты модели.

Архитектурные решения ниже являются предложениями для реализации. Они не изменяют канон, рукописи, профили автора, действующие инструкции или текущую установку плагина. В первом выпуске предполагается один владелец и несколько его устройств. Совместная работа нескольких авторов — отдельный этап с изоляцией аккаунтов.

## Основное решение

Переносимое приложение с собственной серверной частью и браузерным интерфейсом. Codex App Server работает дочерним процессом на том же компьютере/сервере. Автор входит через поддерживаемую авторизацию ChatGPT; модель работает у OpenAI, расходуются доступные лимиты аккаунта. Платный API не используется и не включается автоматически при исчерпании подписки.

```text
Браузер: редактор + чат + база + заметки
                 |
       HTTPS / события / команды
                 |
        Сервер TaleWisp Web
          |        |          |
          |        |          +-- Google adapter --> Docs / Drive
          |        +-- Хранилище --> Markdown / SQLite / файлы
          +-- Agent supervisor
                    |
               stdio JSONL
                    |
             Codex App Server --> модель по подписке
                    |
              MCP TaleWisp + MCP приложения
```

Браузер обращается к серверу приложения; доступ к процессу Codex, локальным путям и токенам остаётся на сервере. Прямой публичный WebSocket App Server не закладывается: документация отмечает экспериментальный статус. Отдельный веб-канал приложения не зависит от транспорта Codex.

## Состав интерфейса

| Область | Содержание | Основные действия |
|---|---|---|
| Проекты | Автор → серия → книги; текущий проект | Открыть, переключить, увидеть доступность источников |
| Редактор | Текст, выделение, комментарии, черновик | Писать, сохранять, сравнить версии, отправить фрагмент агенту |
| Агент | Чат, выбранная модель, статус работы | Обсудить, продолжить, проверить, остановить |
| База знаний | Мир, персонажи, события, связи, источники | Читать, искать, открыть цитату, предложить изменение |
| Заметки | Идеи, вопросы, задачи, ссылки | Создать вручную, связать со сценой или записью |
| Правки | Исходный текст, предлагаемая замена, пояснение | Принять, отклонить, изменить предложение |
| Google Docs | Подключённые документы, вкладки, версия, комментарии | Загрузить, обновить, отправить предложение, открыть оригинал |
| История | Версии и операции с фактическими результатами | Сравнить, восстановить локальную версию, проверить сохранение |
| Настройки | Подключения, модель, лимиты, хранение, резервные копии | Войти, отключить, экспортировать, восстановить |

На широком экране: навигация слева, редактор в центре, переключаемая панель чата/контекста справа. На телефоне — отдельные вкладки с сохранением позиции и выделения. Без обязательной панели технических логов в писательском потоке; детали доступны по раскрытию операции.

## Работа агента

Плагин — инструменты и правила работы; модель — исполнитель. Подключение MCP без загрузки применимых skills и инструкций не считается полной интеграцией TaleWisp.

1. Supervisor запускает закреплённую проверенную версию Codex, выполняет handshake и проверяет аккаунт.
2. Клиент получает доступные модели и лимиты; выбранная модель проверяется по реальному каталогу аккаунта. Не подменять её молча.
3. На проект создаётся изолированный рабочий каталог агента с инструкциями и подключениями. Чат связан с проектом и идентификатором thread App Server.
4. Запрос содержит задачу автора, объект, версию текста, выделение и минимальный контекст. Сервер отмечает происхождение каждого фрагмента.
5. Агент читает релевантные первичные записи через TaleWisp. Для прозы подключаются действующий редакторский протокол, лексический словарь и применимые правила production route.
6. Ответ и события транслируются в интерфейс. Вызов инструмента и факт успешного сохранения показываются раздельно.
7. Семантические изменения возвращаются как предложения. Явное указание автора применить конкретную правку или его собственная запись дают основание для соответствующей операции; повторное согласование не требуется.

Вызовы запуска, возобновления и прерывания чата оборачиваются в версионный адаптер App Server. История Codex хранится его runtime; приложение хранит связь с проектом, отображаемые события и результаты операций. Перезапуск не должен дублировать сообщения или записи.

Состояния: `queued → running → waiting_for_author → completed / failed / interrupted`. Статус ожидания выводится только по фактическому запросу, а не по отсутствию новых токенов. Кнопка «Стоп» прерывает текущий turn и запрещает новые зависимые действия; уже начатую внешнюю запись нельзя объявлять отменённой без проверки результата.

Для первого выпуска — один активный изменяющий запрос на документ. Параллельные чтения допустимы. Отсоединение браузера не запускает новый turn: сервер продолжает отслеживать существующий, а при возвращении восстанавливает состояние.

## Защита авторских данных

Два независимых уровня: технические разрешения Codex и предметные разрешения автора. Одобрение выполнения команды не означает согласование новой механики мира или новой редакции прозы.

Предлагается запускать агента без прямой записи в авторитетное хранилище: доступ к первичным материалам только для чтения, запись в отдельный каталог предложений. Секреты и учётная база приложению доступны, агентному процессу — нет. Если штатный MCP инструментарий требует широкой записи, использовать ограниченную копию рабочего контекста и прокси с явным списком инструментов. Это обязательный технический эксперимент до приёмки, а не доказанная текущая изоляция.

Commit service приложения применяет правки после проверки объекта, авторского основания, версии и точного diff. MCP приложения предоставляет безопасные операции чтения/предложений; штатные изменяющие tools TaleWisp доступны только через контролируемую границу. Фильтрация tools не заменяет файловые разрешения: агент не должен обходить её через shell.

Предлагаемая запись изменения: `proposal_id`, `project_id`, `object_id`, `base_version`, `before_hash`, `patch`, `author_instruction_ref`, `status`, `result_ref`. Статус: `proposed → authorized → committing → verified`, также `rejected / stale / failed / outcome_unknown`.

При несовпадении версии — конфликт и новый diff, без автоматического слияния смысловых изменений. Неизвестный исход внешней записи блокирует повтор этой операции до сверки с источником.

Текущий `talewisp_apply_proposal` уже проверяет исходный хеш, сохраняет backup и заменяет файл атомарно, но принимает `confirmed=true` от вызывающего и не обеспечивает межпроцессный lock или идемпотентность. Для веб-клиента это недостаточная граница: нужен единственный commit-writer на проект, блокировка объекта, повторная проверка под блокировкой, durable operation ID и подтверждение, связанное с сессией автора. Внешний редактор vault может не соблюдать lock: приёмка должна проверить этот конфликт; до решения нельзя обещать отсутствие потери конкурирующих изменений.

## Хранилище и база знаний

Markdown vault остаётся первичным носителем существующей базы TaleWisp. Не переносить канон в SQL и не создавать вторую редактируемую копию по инициативе приложения. SQLite хранит служебные данные и восстанавливаемый поисковый индекс. Рукопись в Google Docs имеет собственный первичный носитель; её локальный snapshot — контекст и черновик, не новая авторитетная версия.

| Данные | Первичный носитель | Производные данные |
|---|---|---|
| Канон, карточки, авторские правила | Существующий Markdown vault | SQLite FTS, связи, версии индекса |
| Локальная рукопись | Отдельный выбранный файл проекта | Черновик, версии, diff |
| Рукопись Google Docs | Конкретные documentId / tabId | Snapshot, локальный черновик, revision binding |
| Заметки автора | Markdown в выбранной области заметок | Поиск и связи |
| Предложения помощника | Отдельное хранилище предложений | Привязки к объектам, решения автора |
| История операций | SQLite приложения | Отчёты и журнал событий |
| Вложения и резервные копии | Файловое хранилище | Метаданные и контрольные суммы |
| Учётные данные | Secret store, отдельно от контента | Только безопасные признаки подключения |

Поиск первой версии — полнотекстовый по словам, формам и метаданным, без обязательного embedding API. Агент может уточнять поиск; цитаты всегда ведут к файлу/разделу или документу/вкладке. Индекс несёт версию источника и пересобирается после внешнего изменения файла. Устаревший индекс не выдаётся за актуальный.

Иерархия автор → серия → книги, общие канон/стиль/источники серии и отдельные сюжеты/сцены книг сохраняется. Гипотезы, архивы, предложения и принятые автором правила имеют разные статусы. Устройство загрузки контекста не переносит стиль одной серии в другую.

Автосохранение относится к авторскому черновику. Применение предложения в канон или оригинал рукописи — отдельная операция. Экспорт включает файлы, служебную базу, схему версии и манифест; секреты исключены. Копия SQLite делается согласованным backup-механизмом, не копированием живого файла без учёта WAL.

## Google Docs

Собственный Google adapter с OAuth пользователя; подключения Google и ChatGPT независимы. Начальный сценарий: выбрать документ, прочитать все нужные вкладки и полный релевантный текст, предложения, комментарии и ответы с пагинацией. Сохранять documentId, tabId, revisionId, UTF-16 диапазон и исходную цитату.

Изменения существующей прозы по умолчанию отправлять как нативные suggestions. Официальная документация Google предусматривает `writeControl.writeMode=SUGGEST` и диапазонные комментарии через Docs API. Текущий `google_workspace.py` готовит планы и отмечает отсутствие writeMode в установленном коннекторе. Поэтому потребуется собственный адаптер; существующую заглушку возможности нельзя объявить рабочей записью.

Перед записью перечитать состояние и потребовать точное совпадение revision и диапазона. Использовать строгий контроль ревизии; при конфликте пересобрать предложение. Сохранять стили и окружающие структуры. Прямую замену разрешать только по явному указанию автора на прямое применение.

После записи: сверить suggestion IDs и диапазон, содержимое комментария и реальную привязку, статусы частичного исполнения, окружающий текст и форматирование. Затем подтвердить в нативном Google Docs наличие accept/reject и попадание комментария в нужный фрагмент. Тест выполняется на специально созданном тестовом документе; управление личным браузером автора требует отдельного разрешения.

Потеря ответа после записи означает `outcome_unknown`: сначала проверка результата, затем решение о повторе. Локальный список правок не имитирует нативные предложения. Неподдерживаемые возможности показываются явно; отсутствие suggestions не включает прямую замену автоматически.

Двусторонней непрерывной синхронизации в первой версии нет: загрузка при открытии, явное обновление, перечитывание перед сохранением. Это уменьшает конфликты и не требует постоянного polling. Не применять преобразование всего документа через Markdown: нужен структурный snapshot со стилями и объектами. Неотображаемые таблицы/изображения сохранять и отмечать; не удалять их при редактировании обычного абзаца.

## Предлагаемый стек

| Компонент | Выбор для первой версии | Причина |
|---|---|---|
| UI | React + TypeScript | Редактор, чат, типизированные события |
| Редактор | ProseMirror / Tiptap, окончательный выбор после spike | Выделения, изменения, комментарии; проверить лицензии выбранных расширений |
| Сервер | Node.js + TypeScript | Управление процессом Codex и потоками событий |
| Runtime агента | Закреплённый Codex CLI App Server | Работа через аккаунт и agent harness |
| TaleWisp | Существующий Python MCP | Переиспользование логики плагина |
| Метаданные и поиск | SQLite + FTS5 | Один переносимый сервис без отдельного сервера БД |
| Контент | Markdown + файловое хранилище | Совместимость с vault и экспорт |
| Google | Собственный OAuth Docs/Drive adapter | Контроль диапазонов, ревизий и нативных операций |

Это предлагаемый стек, версии библиотек и лицензии ещё не выбраны. Модель определяется каталогом аккаунта и выбором автора; её идентификатор не зашивается в интерфейс.

## Размещение

| Режим | Запуск | Данные и учётные записи | Ограничение |
|---|---|---|---|
| Windows локально | Один launcher: сервер + Codex + Python | Локальные каталоги и отдельный runtime профиль | Для удалённой работы компьютер должен быть доступен |
| Linux сервер | Сервис ОС либо Docker Compose | Постоянные volumes, отдельный профиль владельца | Требуется установка/обновление и поддерживаемый sign-in |
| Гибрид | Веб-интерфейс отдельно, runtime на собственном хосте | Авторитетные данные на хосте владельца | Нужен защищённый канал к серверу приложения |

Локально слушать loopback. Для доступа с телефона — отдельный явно включённый режим с аутентификацией; предпочтительно VPN либо HTTPS reverse proxy. Наличие LAN не заменяет проверку доступа. Серверный профиль включает TLS, session cookies, Origin/CSRF проверки, ограничение частоты и размера запросов и отсутствие публичного доступа к runtime/файлам/секретам.

SQLite и vault должны находиться на одном локальном файловом томе выбранного хоста. Не использовать общий сетевой диск для живой SQLite. Сервер и локальная установка не пишут одновременно в одну базу: перенос через backup/export/import с проверкой версии. Одновременное зеркалирование — отдельная задача.

ChatGPT sign-in выполнять штатным flow на runtime-хосте; для headless проверять device-code доступность у аккаунта. Не копировать токены из браузера и не обещать бесконечный доступ по подписке. При лимите UI сохраняет черновик и показывает фактический статус; платный fallback запрещён. Для нескольких пользователей нужны отдельные runtime и авторизации, это не входит в первую версию.

## Этапы и критерии приёмки

| Этап | Результат | Проверяемая приёмка |
|---|---|---|
| A. Agent spike | Минимальный собственный чат | Реальный sign-in без API key; ответ выбранной модели; лимит; stop; reconnect; Windows и Linux |
| B. TaleWisp boundary | Изолированный агент с контекстом | Чтение тестового vault; применимые instructions; предложение без записи; попытка обхода записи запрещена |
| C. Редактор и база | Рабочее локальное пространство | Выделение, черновик, поиск с источниками, note, conflict, restart recovery, backup restore |
| D. Google spike | Полный нативный цикл на тестовом Docs | Suggestion + anchored comment; accept/reject; revision conflict; no duplicate after unknown outcome; сохранённые стили |
| E. Переносимый выпуск | Локальный и серверный запуск | Установка на чистом Windows/Linux; закрытый доступ; экспорт/импорт; идентичные данные после восстановления |

Следующий шаг реализации — A и D как технические прототипы: они проверяют внешние зависимости до разработки большого интерфейса. Отрицательный результат не отменяет требование; фиксируется точный недоступный путь и решение обсуждается с автором. B отдельно проверяет техническое обеспечение границы авторских правок.

Не включать в начальный объём: совместное редактирование несколькими авторами, публичную регистрацию, автоматическое изменение канона, скрытые циклы переписывания, перенос StoryArt генерации в TaleWisp, автоматическую публикацию и постоянную синхронизацию двух vault. Возможность расширения сохраняется, но это отдельные задачи.

## Проверенные опоры и оставшиеся проверки

Проверено чтением исходников: TaleWisp 0.6.3 — Python MCP; конфигурация запуска сейчас Windows PowerShell; Google planner не выполняет нативную запись suggestions через установленный connector. Windows launcher нужно дополнить Linux запуском непосредственно Python, без PowerShell-зависимости.

Проверено документацией: App Server предназначен для собственных клиентов, предоставляет управление чатами, события, авторизацию ChatGPT и лимиты; основной транспорт stdio. Google Docs описывает нативные suggestions и комментарии к диапазону. Это не runtime-доказательство доступности функций конкретному аккаунту.

Не проверено исполнением: sign-in и выбранная модель на будущем сервере, загрузка полного TaleWisp workflow новым runtime, техническая read-only граница, нативная Google запись и её отображение, лицензия редактора, целевые объёмы базы и стоимость хостинга. Эти вопросы имеют конкретные acceptance gates выше.

App Server и особенно его удалённые транспорты развиваются; перед выпуском проверить статус поддержки выбранной версии, зафиксировать её и прогнать контрактные сценарии. Официальное описание собственного клиента не является обещанием стабильности всех протокольных возможностей в production.
