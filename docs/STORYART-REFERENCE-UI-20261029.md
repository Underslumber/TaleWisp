# Выбор референсов в WebUI

В форме генерации добавлен блок «Использовать референсы». Подключение остаётся явным; внутри по умолчанию выбран режим «С подтверждением». Последний режим запоминается в текущей рабочей области браузера. Выборы разных книг разделены.

| Режим | Как выбирается набор | Когда отправляется задание на генерацию |
|---|---|---|
| Авто | Агент подбирает набор; ход и результат видны в блоке | Кнопка отправки ждёт готового набора и продолжает без отдельного подтверждения референсов |
| С подтверждением | Агент показывает выбор, объяснение и альтернативы | После явного подтверждения набора и нажатия отправки |
| Вручную | Автор выбирает из всей библиотеки и задаёт назначение источников | После подтверждения ручного набора и нажатия отправки |

## Схема работы

```text
Описание сцены / персонажа
  |
  +-- Авто ------------> подбор агента ------------> готовый набор --+
  |                                                                |
  +-- С подтверждением -> предложение + альтернативы                |
  |                         |                                      |
  |                         +-> принять ---------------------------+--> отправка в StoryArt
  |                         +-> заменить один источник -> принять --+    -> подготовка вложений
  |                         +-> закрепить часть -> переподбор ------+    -> генерация и QA
  |                                                                |
  +-- Вручную ---------> библиотека -> набор -> подтвердить ---------+
```

Подтверждение набора не утверждает новое тело, одежду или личность персонажа и не является утверждением итогового изображения. Допуск реального вложения проверяет StoryArt.

## Библиотека и карточки

Категории показывают назначение, источник выбирается независимо. Список и счётчики читаются из действующей классификации StoryArt. Поддержаны поиск, фильтр субъекта, страницы по 24 карточки и переход к связанным ракурсам одной позы. Лист с несколькими фигурами и вырезки сохраняют свою исходную семантику.

Карточка показывает изображение либо причину отсутствия разрешённого просмотра, название, ракурс, источник и честный статус кандидата. Изображение открывается крупно. Техническая группа и примечания находятся в раскрываемых деталях. Непроверенные записи не исчезают из каталога и не получают выдуманный PASS.

Выбранный набор виден отдельно. «Заменить» меняет только выбранную карточку; остальные сохраняются. «Закрепить» защищает источник при переподборе. Поле «Что изменить в подборе?» передаёт поправку в тот же выделенный запрос. Плавающая строка сохраняет доступ к набору и подтверждению при прокрутке библиотеки. На узком экране карточки идут в две колонки без горизонтального переполнения.

## Изменения и ошибки

При изменении промпта, персонажа, стиля, параметров или файлов старый план нельзя использовать молча. Агентский набор нужно обновить. Для ручного набора есть явное «Обновить набор для задания» с сохранением локально выбранных карточек и повторной проверкой источников.

Потеря ответа на запуск сохраняет точный UUID и исходное тело запроса. «Обновить статус» только читает тот же план; «Повторить ту же попытку» использует прежний UUID, не создавая новый агентский запрос. Изменение режима во время неопределённого исхода запрещено.

Автоматическая отправка приостанавливается при выходе из формы, смене книги, отключении референсов или изменении задания. Отказ подбора до отправки генерации не выдаётся за неизвестный исход генератора.

## Фактические проверки и ограничения

В браузере проверены реальные карточки текущей библиотеки, ручной выбор, предложение с заменой и подтверждением, а также автоматический переход от готового плана к отправке. Журнал фикстуры подтверждает передачу точного ID выбранного плана. При ширине 390 px сетка имеет две колонки, ширина документа равна 390 px. Локальная визуальная фикстура отключает реального агента и генератор; это не приёмка их работы. Переподбор и защита исходов дополнительно проверяются целевыми тестами. 97 целевых тестов: 95 прошли, 2 пропущены из-за недоступных symlink. Исправления UI прошли независимое Sol-ревью; первый аудит Opus не нашёл блокирующих дефектов кода; закрытие замечания о консультации проверяется отдельно.

Консультация Web Advisor получена из существующего завершённого чата «UX спецификация референсов»: https://chatgpt.com/c/6ae36429-e850-83e8-86c2-159b465cb2c7 . Повторного запроса не было. Сохранён доступный API-фрагмент 20000 символов; окончание ответа недоступно, полный текст не заявляется прочитанным.
Реализация соответствует основным рекомендациям: три режима в форме, подтверждение по умолчанию, раздельные выбранные/альтернативы, точечная замена, закрепление и переподбор, полный каталог с назначением отдельно от источника, точные ID/роли/SHA, снимок задания и защита устаревшего плана, один UUID при неизвестном исходе. Дополнительно применены честные типы карточек: ракурс одной позы, групповой скетч, фрагмент листа, одежда, учебный пример; родительский лист не назван ракурсами.
Отличия от необязательных предложений:24 карточки вместо36; встроенная библиотека вместо новой панели; ручной просмотр доступен до заполнения задания, проверка и подтверждение атомарны. Устаревшую отправку блокирует существующий обработчик с сообщением; отдельное отключение кнопки не вводилось. Это сохраняет проверенные контракты без новой механики.

## Поправка автора: поза и визуальные ракурсы

Opus 5.5 заменил отклонённый native select однострочной лентой реальных миниатюр. Одна карточка на группу POSE_ATLAS; клик и стрелки/Home/End меняют локальный ракурс, активная кнопка выделена золотом, подпись показывает ракурс и индекс. На узкой карточке лента прокручивается горизонтально. Новый модельный запрос при переключении не создаётся. Для выбранной позы сохраняются назначение, закрепление и необходимость повторного подтверждения. Остальные скетчи/листы не объединяются как ракурсы.

Реальный подбор GPT-6-Luna/high показал 1 рекомендованную и 5 альтернативных поз, по 5 ракурсов. Первый ответ отклонён валидатором из-за пробела в SHA256; одна повторная попытка через UI вернула корректный набор. Фактическая модель подтверждена turn_context. Новый UI проверен в HTTPS: шесть карточек, все 30 миниатюр загружены; клик и клавиатура меняют изображение и фокус. 101 PASS / 1 SKIP. Новая мобильная визуальная проверка не подтверждена: viewport override не изменил фактическую ширину2560. Изображения не генерировались.
