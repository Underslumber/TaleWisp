# Живой мир

В основном меню TaleWisp появился раздел **Живой мир**. В нём работает включённый WorldX (MIT, upstream commit `edb4976de5963457dfbf5d2171355270a4ca1e79`) с адаптером TaleWisp. Запускается отдельный ограниченный процесс для каждой ветки. Исходный HTTP-сервер WorldX не запускается.

Игровой вид использует Phaser и оригинальные компоненты WorldX `CharacterSprite` / `CameraController`: спрайты, ходьбу между подтверждёнными позициями, масштабирование, слежение камеры и реплики над участниками. Вместо прежнего SVG-графа отображается лесной ландшафт с дорогами. Земля, деревья и игровые фигурки — условное сценическое оформление, а не новые канонические объекты или утверждённая внешность персонажей. Положение, доступные места, встречи, реплики и память приходят из серверной проекции ветки. Сцену можно развернуть; переключение истории и роли перестраивает её из соответствующего снимка, не вызывает модель и не показывает скрытых участников.

Phaser загружается только при открытии игровой сцены. Собранный браузерный модуль включён в `web-client/public/vendor/living-world-stage.js`, исходник — `web-client/stage`. После изменения исходника пересоберите его:

```sh
node scripts/build-living-world-stage.mjs
```

## Подготовка

Текущая поддерживаемая среда модуля — Windows, Node 24+, Python 3 и npm. Остановка дерева дочерних процессов проверена для Windows; на других ОС модуль явно отказывает до создания данных или процессов. Из этого checkout выполните:

```sh
node scripts/setup-living-world.mjs
```

После этого запускайте основной интерфейс TaleWisp обычным способом. Зависимости WorldX зафиксированы в `vendor/worldx/server/package-lock.json`; настройка не требует исходного исследовательского каталога `.agent` или соседнего checkout TaskWarden. Для варианта Codex нужен установленный авторизованный Codex CLI. Контроллер TaskWarden включён в `vendor/taskwarden`.

## Перенос и управление

1. Выберите серию и откройте «Живой мир → Перенести текущую серию». Импорт сохраняет источники, статусы, временные привязки и ссылки. Дополнительную исходную сцену можно указать относительным путём в серии.
2. Прочитайте источники и составьте постановку: места, персонажи, их начальные знания, направленные переходы и длительности. Неизвестные координаты, даты и механики не достраиваются автоматически. Полный состав и планы доступны в редакторе постановки.
3. Подтвердите создание отдельной ветки. На карте выберите место и отправьте участника в путь. «Один шаг» продвигает время; «Продолжить» имеет конечный горизонт 1–24 такта. Закрытый переход останавливает путь, продолжение требует решения автора.
4. Добавляйте местные события сразу или с задержкой. Переключайте обзор автора и восприятие персонажа. История показывает записанные снимки без модельных вызовов; ответвление копирует память, пути, время и состояние движка.

Мир исполняет утверждённый граф, планы, доступные действия объектов, встречи и события. Текстовые правила из базы сохраняются с источниками и пометкой `executable:false`; произвольный закон магии не становится исполняемой механикой от одного импорта. Это граница текущего адаптера, видимая при постановке.

## Самостоятельность и API

Доступны три режима: действия автора, заданные планы NPC и решения модели. Автономия героя включается отдельно. Автор выбирает участников и явно выдаёт дополнительный лимит вызовов. Неудачные попытки также расходуют этот лимит; откат снимка его не восстанавливает.

Два варианта модели:

| Вариант | Подключение | Ограничения |
|---|---|---|
| Codex | Авторизованный локальный CLI, выбор модели проекта | TaskWarden проверяет версию ТЗ, роль, модель и хеш входа перед запуском |
| OpenAI API | «API для мира»: ключ, при необходимости project ID, сохранить и проверить доступ | Тот же TaskWarden; отдельный лимит вызовов и локальный бюджет в долларах; без автоматической подмены варианта |

Ключ хранится сервером вне снимков мира и не возвращается браузеру, не передаётся WorldX или в пакет персонажа. Поддерживается также серверная переменная `OPENAI_API_KEY`. Кнопка проверки запрашивает список моделей и не запускает генерацию. Запросы генерации идут только в официальный Responses API с `store:false`, без инструментов и со строгой JSON-схемой. Текущий API-вариант: `gpt-6.1-sol`, medium/high в соответствии с выбором проекта; при несовместимом выборе будет явная ошибка.

Программные $100 должны быть активны в организации OpenAI API, к которой относится ключ. TaleWisp не активирует кредит и не знает остаток. Расход в интерфейсе — локальная оценка по токенам и консервативный резерв перед каждым вызовом, а не баланс аккаунта. Резерв включает максимальный ответ и не освобождается при ошибке. Актуальные условия: [кредиты ChatGPT API](https://developers.openai.com/api/docs/guides/chatgpt-api-credits), [модель и цены](https://developers.openai.com/api/docs/models/gpt-6.1-sol). Зафиксированная оценка на 12.11.2026: $2/$10 за миллион входных/выходных токенов; при изменении тарифа оценку нужно обновить.

## Память и канон

Источники канона доступны только импортёру для чтения. WorldX получает разрешение читать код движка и каталог своей ветки и писать только в свою ветку; ключей и пути канона у него нет. Ветка хранится в `<dataDir>/living-world/branches`, библиотека импорта — отдельно. Автоматического переноса результатов обратно в канон нет.

Каждое воспоминание имеет владельца, время получения, тип и источник. Сначала ограничиваются владелец/время/аудитория, затем выбираются релевантные воспоминания. Собеседник сообщает слух, а не объективную истину; чужие цели и мысли не включаются в пакет роли. Одни и те же правила проекции применяются к живому состоянию и истории. Автор видит всю ветку.

У нативной роли Codex отключены не только инструменты чтения, браузера и коннекторов, но и исполнитель Code Mode; конфигурация строгая, несовместимая версия CLI должна завершить вызов ошибкой. На текущей версии проверка чтения отдельного тестового файла получила `code-mode host is disabled` и не раскрыла его содержимое. Это ограничение относится к модельной роли; основной сервер по-прежнему читает выбранные источники для импорта.

Снимок публикуется атомарно после закрытия SQLite движка. При ошибке или отмене незавершённый такт не становится текущим. Повтор запроса с тем же ID не применяет действие заново; устаревшая ревизия отклоняется. Пауза останавливает дальнейшие такты и отменяет принадлежащие ветке модельные процессы.

Если процесс оборвался между сохранением снимка и сменой указателя, неопубликованный каталог сохраняется как `orphan-*`, а выполнение продолжается от последнего опубликованного состояния. Счётчик вызовов и API-резерв хранятся вне снимков и читаются заново при выдаче автором лимита. Падение worker и закрытие модуля отменяют очередь и завершают принадлежащие ему деревья модельных процессов.
