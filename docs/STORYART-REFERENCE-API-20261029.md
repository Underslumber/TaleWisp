## Источник классификации

Владелец данных — `D:/Projects/StoryArt/tools/reference_pool_manager.py`. Read-only адаптер TaleWisp использует его `records`, `public_record` и `select`, а не собственную копию классификации. Категории строятся из `config/reference_categories.json`; пулы — из `config/reference_pools.json`.

Категория задаёт назначение, пул задаёт происхождение. Один файл может иметь несколько категорий. Атлас сохраняет `group_id` и `angle`; вырезки сохраняют родителя и происхождение. Они не объявляются ракурсами одной позы. Выключенные NATURAL/SKETCH и не подключённый в общий менеджер OLCHAS не добавляются обходным сканированием.

`generationEligible:false` означает, что каталог и подтверждение подбора не заменяют подготовку вложений в StoryArt. Если владелец не возвращает путь для просмотра, TaleWisp не пытается его восстановить. Для разрешённого просмотра повторно проверяются актуальная ревизия и SHA-256 реального файла; пути и символические ссылки проверяет существующий `storyArtSafeFile`.

## HTTP

Все маршруты требуют существующую сессию WebUI. Для каталога и планов обязателен актуальный `x-storyart-scope`. POST сохраняет существующую проверку Origin. Рабочая область определяется сервером, а не полем тела запроса.

| Метод | Путь | Результат |
|---|---|---|
| GET | `/api/storyart/references` | `revision`, категории со счётчиками, пулы с ролями, страница записей |
| GET | `/api/storyart/reference-image` | Проверенное изображение или конкретный отказ |
| POST | `/api/storyart/references/plans` | Новый либо ранее созданный по тому же UUID подбор |
| GET | `/api/storyart/references/plans/:id` | Собственный план; при ожидании читает только его выделенный чат |
| POST | `/api/storyart/references/plans/:id` | Проверка выбранного набора и необязательное подтверждение |
| POST | `/api/storyart/references/plans/:id/regenerate` | Поправка в том же чате с закреплёнными источниками |
| POST | `/api/storyart/jobs` | Существующий запуск с необязательным `referencePlanId` |

Фильтры каталога: `category`, `pool`, `subject`, `q`, `tag`, `offset`, `limit` (1–100; по умолчанию 36). `subject` — только фильтр известных метаданных, не результат новой классификации. Поиск не является агентским подбором.

Просмотр изображения принимает `pool`, исходный `id`, `revision`, `sha256` из карточки. Изображения не встраиваются в ответы JSON и не публикуются в отдельную общедоступную библиотеку.

## План

Создание принимает `requestId` (постоянный UUID попытки), `workspaceRevision`, `mode` (`auto`, `confirm`, `manual`), необязательный `subject` (`MALE`, `FEMALE`) и `target` — фактический будущий запрос генерации. Повтор одного UUID с тем же содержимым не создаёт второй чат. Другой payload или другая область с тем же UUID дают 409. Неизвестный исход не разрешает автоматическую повторную отправку.

Привязка к заданию включает тип операции, стиль, персонажа, буквальный промпт, исходные референсы стиля, загрузки и параметры генерации. Изменение этих полей требует нового подбора. Поле `bodyLibrary` исключено из отпечатка, поскольку подключение нового плана задаёт сам `referencePlanId`.

```text
manual -> draft -> awaiting_confirmation -> ready
auto/confirm -> dispatching -> selecting
                              -> ready (auto)
                              -> awaiting_confirmation (confirm)
                              -> review_required (нет корректного набора)
dispatching/send failure with unknown outcome -> unknown
ready -> in_use (атомарная резервация конкретным requestId генерации)
in_use -> ready (только доказанный отказ до отправки)
```

Обновление плана принимает `workspaceRevision`, `items` и `confirm:true/false`. Каждый item содержит исходные `pool`, `id`, разрешённую `role`, `sha256`. Проверка делегирована менеджеру StoryArt; источник не становится утверждённым телом/одеждой/личностью от подтверждения набора. После передачи набора в работу его нельзя изменить для другой генерации.

Переподбор принимает `workspaceRevision`, `message`, `pinned` — массив ключей `pool:id` из текущего выбора. Это поправка существующего выделенного чата, а не новый запрос генерации. Ответ привязан к номеру `round`; старый ответ не закрывает новый раунд. Нарушение закреплений переводит план в `review_required`.

Агентский результат читается только из последнего структурированного блока `REFERENCE_SELECTION_BEGIN` / `REFERENCE_SELECTION_END`, с `round`, `selections`, `alternatives`, `reason`. Источники ответа повторно проверяются менеджером, ограничены 6 выбранными и 6 альтернативами. Отсутствие корректного результата не превращается в выдуманный выбор.

## Группы поз и модель подбора

`GET /api/storyart/references?grouped=1` пагинирует группы POSE_ATLAS (24 карточки); `total` считает карточки, `imageCount` — совпавшие изображения. В `views` возвращаются реальные допустимые ракурсы группы с текущими ID/SHA256/previewUrl. Поиск по одному ID также возвращает доступных соседей той же группы после фильтрации pool/category/subject. Без grouped сохраняется прежняя пагинация изображений. Скетчи, листы и кропы не схлопываются в группы поз.

Только refs-UUID / STORYART_REFERENCE_SELECTION_ONLY задачи создаются и продолжаются с `gpt-6-luna`, `high`; обычная иллюстрация сохраняет свой маршрут. Финальный ответ подбора читается с лимитом20000 без промежуточныхoutputs. Возврат к видимой форме возобновляет опрос.
